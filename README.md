# SalimGPT Global

**Research-Based Documentary Media — Human-Led. AI-Assisted. Editorially Reviewed. Multilingual.**

SalimGPT Global is the central website for **SalimGPT**, an independent, research-based, multilingual documentary media brand.

SalimGPT is **not an AI chatbot or AI model**. Artificial intelligence may assist selected parts of documentary research, drafting, language adaptation, visual development and production, while **editorial judgment, source verification, fact-checking, creative direction, review and final publication approval remain human-led**.

# Editorial Model

SalimGPT follows a:

> **Human-Led, AI-Assisted, Editorially Reviewed**

production model.

AI tools may assist with selected tasks, including:

- Research organization
- Document comparison
- Draft development
- Translation support
- Localization
- Transcription
- Visual concept development
- Synthetic media development
- Production support
- Consistency checks

AI output is not automatically treated as verified evidence.

Important factual claims should be checked against appropriate underlying sources.

Human editorial responsibility remains central to:

- Research decisions
- Source selection
- Evidence assessment
- Interpretation
- Fact-checking
- Attribution
- Narrative structure
- Creative direction
- Visual context
- Corrections
- Final approval

# Page Image Convention

Content pages use page-specific images stored under:

    assets/pages/

The preferred naming convention is:

    <page-slug>-1.webp
    <page-slug>-2.webp

Example:

    fact-checking-1.webp
    fact-checking-2.webp

---

## Primary Page Image

The `-1.webp` file is generally used as:

- Primary visible page image
- Hero image
- Open Graph sharing image
- Twitter/X sharing image

Preferred dimensions:

    1200 × 630

---

## Supporting Page Image

The `-2.webp` file is generally used as a supporting visual inside the page.

Preferred dimensions:

    1200 × 800

---

# Social Sharing Images

Each completed content page should use its own page-specific sharing image.

Example:

    <meta
      property="og:image"
      content="https://salimgpt.github.io/salimgpt/assets/pages/fact-checking-1.webp"
    >

And:

    <meta
      name="twitter:image"
      content="https://salimgpt.github.io/salimgpt/assets/pages/fact-checking-1.webp"
    >

A generic social image should not replace the dedicated image when a page-specific image exists.

# Documentary Research Principles

Research pages should avoid presenting unsupported certainty.

Relevant editorial practices include:

- Verify important claims
- Prefer appropriate underlying sources
- Distinguish primary and secondary sources
- Cross-check when appropriate
- Preserve uncertainty
- Attribute source-specific claims
- Review numerical context
- Review translations
- Review visual implications
- Separate evidence from interpretation

# Corrections

SalimGPT distinguishes between different kinds of post-publication changes.

These may include:

### Correction

Fixes material that was wrong, misleading or materially incomplete.

### Update

Reflects later developments, evidence or data.

### Clarification

Improves wording when the original presentation could reasonably be misunderstood.

### Technical Fix

Addresses presentation or interface problems that do not materially affect factual meaning.

Correction requests can be directed through:

    /help/correction-request/

# Relative Path Convention

For a root-level page, the correct relative path depends on the page location.

For a page two directories below the repository root, such as:

    /how-we-work/fact-checking/index.html

shared root assets typically use:

    ../../assets/
    ../../css/
    ../../js/
    ../../data/

Sibling How We Work routes typically use:

    ../editorial-standards/
    ../production-process/

Always verify the depth of the current page before creating relative paths.

# Development Principles

When adding or updating a page:

1. Use the correct repository-relative paths.
2. Preserve canonical brand assets.
3. Include semantic HTML.
4. Add a unique title and description.
5. Add a canonical URL.
6. Use a page-specific Open Graph image.
7. Use the same primary image for Twitter/X metadata.
8. Include visible page-relevant imagery.
9. Add structured data where appropriate.
10. Preserve accessible navigation.
11. Maintain responsive behavior.
12. Keep editorial copy factual and supportable.
13. Avoid invented claims.
14. Maintain the human-led, AI-assisted positioning.
15. Add the route to the sitemap when appropriate.
